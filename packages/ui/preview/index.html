How Astrodock apps are built

One design system for every app on the platform. Tokens make primitives, primitives make components, components make page types, and every screen is one of the page types. An agent building an app reads REFERENCE.md; a person who knows one app finds the next one works the same way.

How it builds on itself

1Tokens

Every color, size, radius, weight and shadow. An app changes its brand here and nowhere else.

2Primitives

One control shape (buttons, inputs, selects), one item shape (menus, options, navigation), one surface, one avatar, one checkbox.

3Components and pages

Built only from primitives. Pages are built only from components. scripts/check.js fails on anything else.

Principles

  1. 01
    1
    Content leads.
    Chrome is one compact bar. The title, what matters and the main action are visible without scrolling.
  2. 02
    2
    One way to do each thing.
    One select, one modal, one checkbox, one way to filter. A screen never invents its own control.
  3. 03
    3
    You always know where you are and how to get back.
    A back button names the parent; the URL holds the tab, filters and sort.
  4. 04
    4
    Actions are buttons; navigation is links.
    A button does something. A link goes somewhere and opens in a new tab when asked.
  5. 05
    5
    Shading, not lines.
    Surfaces separate by background and elevation. Borders are kept for inputs.
  6. 06
    6
    Color means something.
    The accent marks what can be clicked or is selected. Green, amber and red mean success, attention and danger, always with an icon and a word.
  7. 07
    7
    Every state is designed.
    Loading, nothing yet, no matches, error, no access and running in the background each have a set look and words.
  8. 08
    8
    Nothing is lost by accident.
    Unsaved changes are guarded, removals can be undone, irreversible deletes are confirmed.
