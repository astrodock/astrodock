How Astrodock apps are built

One design system for every app on the platform: the stylesheet, the parts of an app, the page types, how people move between pages, what every state looks like, and how the words read. An agent building an app follows it; a person using two apps finds them work the same way.

The model

1 · Shell
Every app has the same frame

A top bar with the app's name, up to six sections and the person's menu. Apps with more sections use the sidebar shell. Nothing else is permanent chrome.

2 · Pages
Every screen is one of eight page types

Collection, record, create and edit, settings, dashboard, background work, step by step, and system pages (sign-in, errors). Each has a fixed anatomy, so new screens are assembled, not designed.

3 · Parts
Pages are made of kit components

Buttons, fields, selects, tables, filters, modals, drawers, menus, toasts and the rest. One way to do each thing; no screen invents its own control.

Principles

Content leads. Chrome is one compact bar. The page title, what matters and the main action are visible without scrolling.
One way to do each thing. One select, one modal, one way to filter, one place for actions. Consistency beats cleverness.
You always know where you are and how to get back. Every page below a section has a back button naming its parent, and the URL holds the tab and filters.
Actions are buttons; navigation is links. A button does something. A link goes somewhere and opens in a new tab when asked.
Shading, not lines. Surfaces separate by background and elevation. Borders are kept for inputs.
Color means something. The accent marks what can be clicked or is selected. Green, amber and red mean success, attention and danger, always with an icon and a word.
Every state is designed. Loading, empty, no results, error, no access and working-in-the-background each have a set look and words.
Nothing is lost by accident. Unsaved changes are guarded, deletes can be undone or are confirmed, and long work runs in the background with progress.
