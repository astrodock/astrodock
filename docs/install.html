Get started

Install & run

Astrodock ships as a single Docker stack. You'll copy a config file, fill in a few values, and run one command. Two ways to do it: locally to try it out, or on a server for a real, public install.

Before you begin

  • Docker with the Compose plugin. Check with docker compose version. (Docker Desktop on Mac/Windows, or Docker Engine on Linux.)
  • For a server install: a domain name and the ability to add DNS records, plus a box reachable on ports 80 and 443.
  • Optional: a GitHub token, only if you want apps to redeploy automatically on git push. You can skip it and deploy from your laptop instead.

Get the code

git clone https://github.com/your-org/astrodock.git
cd astrodock

Configure

Copy the example config to .env and open it in your editor:

cp .env.example .env

A few values you must set. Generate each secret with openssl rand -hex 32:

SettingWhat it is
ASTRODOCK_ADMIN_JWT_SECRETSigns your dashboard login session. Random secret.
ASTRODOCK_SECRET_KEYEncrypts stored secrets at rest. Random secret. Strongly recommended.
ASTRODOCK_RUNNER_TOKENInternal password between the two Astrodock services. Random secret.
ASTRODOCK_PG_PASSWORDPassword for the bundled database. Random secret.
ASTRODOCK_OBJECTSTORE_SECRET_KEYPassword for the bundled file storage. Random secret.
ASTRODOCK_ADMIN_EMAIL / ASTRODOCK_ADMIN_PASSWORDYour first dashboard login. The admin user is created on first boot.
ASTRODOCK_BASE_DOMAINThe domain apps live under. localhost locally; your real domain on a server.
ASTRODOCK_TLS_MODEHow HTTPS is handled: off, internal, or auto (explained below).

Keep .env private

It holds your secrets. It's already in .gitignore — never commit it.

Choosing a TLS mode

TLS_MODEUse it when…What happens
offTrying it on your laptopPlain HTTP. Simplest. Apps at http://<sub>.localhost.
internalOn a LAN with no public DNSAstrodock issues its own certificates (your browser will warn the first time).
autoOn a public server with a domainReal, free Let's Encrypt certificates, renewed automatically.

Option A — Run locally

Best for trying Astrodock or developing apps. In your .env:

ASTRODOCK_BASE_DOMAIN=localhost
ASTRODOCK_TLS_MODE=off

Then bring the stack up:

docker compose up -d

That's it — your dashboard is at http://admin.localhost and your apps will live at http://<subdomain>.localhost.

Why .localhost works with no setup

Browsers automatically point any *.localhost name at your own machine, so admin.localhost and notes.localhost just work — no DNS or hosts-file editing needed.

Option B — Run on a server

For a real, internet-facing install. In your .env:

ASTRODOCK_BASE_DOMAIN=apps.example.com
ASTRODOCK_TLS_MODE=auto
ASTRODOCK_ACME_EMAIL=you@example.com

  1. Point DNS at your server

    Add a wildcard DNS record so every app subdomain resolves:

    *.apps.example.com   A   <your server's IP>

    This one record covers admin.apps.example.com and every app. Full walkthrough in Custom domains & DNS.

  2. Open the web ports

    Make sure ports 80 and 443 are reachable (firewall / security group). Only those two need to be public.

  3. Bring the stack up

    docker compose up -d

    Caddy will fetch HTTPS certificates automatically the first time each subdomain is visited.

Check it's running

docker compose ps        # all services should be "Up" (postgres "healthy")
docker compose logs -f api   # watch the control plane start up

You should see the control plane run its database setup, create your admin user, and start listening.

Log in

Open the dashboard — http://admin.localhost (local) or https://admin.<your-domain> (server) — and sign in with the ASTRODOCK_ADMIN_EMAIL / ASTRODOCK_ADMIN_PASSWORD you set.

First boot

The admin account is seeded from your .env the first time the stack starts. Change the password after logging in, or rotate it via .env + a restart.
