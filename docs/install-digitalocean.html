Install on a server

Run on DigitalOcean

The friendliest way to get Astrodock online if you don't already have a server. We'll create a small machine (a "droplet"), point your domain at it, install Docker, and start Astrodock. Plan for about 20–30 minutes the first time.

You'll need

A DigitalOcean account, a domain name (from any registrar), and an SSH key (DigitalOcean will help you add one). Rough cost: a suitable droplet is about $12/month.

  1. Create a droplet

    In DigitalOcean, choose Create → Droplets:

    • Image: pick the Docker image under the Marketplace tab. (That comes with Docker already installed, so you can skip Step 5. If you'd rather use a plain Ubuntu 24.04 LTS image, that's fine too.)
    • Size: a Basic plan with at least 2 GB RAM (1 vCPU). Astrodock itself is comfortable in less, but it builds your apps on the box, and 1 GB can run out of memory during a build.
    • Authentication: add your SSH key (recommended over a password).

    Create it, and note the droplet's public IP address.

  2. Point your domain at the droplet

    Decide which domain your apps live under. We'll use apps.example.com as the example — every app becomes <name>.apps.example.com, and the dashboard is admin.apps.example.com.

    The easiest route is to let DigitalOcean manage DNS. In DigitalOcean go to Networking → Domains, add your domain, then create one wildcard record:

    Type: A    Hostname: *.apps    Will direct to: <your droplet IP>

    That single record covers the dashboard and every app. (At your registrar, set the domain's nameservers to DigitalOcean's, or skip DO DNS and add the same wildcard A record at your registrar instead.) Full details and other registrars: Custom domains & DNS.

    Do this now if you can — DNS changes take a few minutes to spread, so starting early means it's usually ready by the time you need it. If you'd rather not, that's fine: the setup wizard in step 7 shows you this same record and checks it for you.

  3. Open the firewall

    Under Networking → Firewalls, create a firewall and attach it to your droplet, allowing inbound SSH (22), HTTP (80), and HTTPS (443). Only those three need to be open.

    Use your provider's firewall rather than ufw on the droplet: Docker inserts its own routing rules ahead of ufw's, so a ufw deny on a published port doesn't actually block it. Astrodock doesn't manage the firewall for you, but Settings → Readiness warns you if anything beyond 80/443 ends up published to the internet.

  4. Connect to the droplet

    ssh root@<your droplet IP>

  5. Install Docker

    Skip this if you used the Docker Marketplace image. On a plain Ubuntu droplet:

    curl -fsSL https://get.docker.com | sh

    Confirm it's ready:

    docker compose version

  6. Install Astrodock — one line

    curl -fsSL https://get.astrodock.dev | sh

    That is the whole install. It downloads the compose file, generates every secret for you, pulls the prebuilt images, and starts the stack. There is no source code to clone and nothing to build on the droplet, so it finishes in about a minute.

    When it's done it prints the address to open — your droplet's IP.

    Prefer to build from source?

    Clone the repository instead, then run ./scripts/setup.sh and docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build. Same result; it just builds the images on the droplet rather than pulling them.

  7. Finish setup in your browser

    Open http://<your droplet IP>. Astrodock starts up unconfigured and serves a short setup wizard there, which walks you through the rest:

    1. Create your administrator account. It asks for a one-time token that Astrodock printed to its log — this is what stops anyone else claiming your server. Get it with: 
      cd /opt/astrodock && docker compose logs api | grep -A2 'first-run setup'
    2. Enter your domain. The wizard shows you the exact DNS record to create, filled in with your server's IP, and a Check DNS button that tells you whether it's live yet — so you find out here rather than after a certificate has failed.
    3. Turn on HTTPS. Give it a contact email and save. Astrodock republishes its routing and hands you the link to your real dashboard.

    From then on your dashboard lives at https://admin.apps.example.com and the IP address stops being the way in. The certificate is issued on your first visit, so that very first load can take a few seconds.

Would rather not use the browser at all?

Every step of the wizard has a flag. ./scripts/setup.sh --domain apps.example.com --email you@example.com --admin-email you@example.com --admin-password '…' configures the lot up front, and the platform boots straight to a login page. The wizard exists because it can check your DNS for you; it is not the only way in.

Other beginner-friendly hosts

Prefer somewhere else? The steps are nearly identical on any provider — create an Ubuntu server, point a wildcard DNS record at it, then follow Steps 4–10 above. Good options include Hetzner Cloud (very cheap), Linode/Akamai, Vultr, and AWS Lightsail. See Your own server / any VPS for the provider-agnostic version.
