# Building apps for Toolstead

The long-form companion to the root `AGENTS.md`. Read that first for the contract; this doc has
the full environment-variable catalog, worked examples for every app shape, and troubleshooting.

---

## App shapes

| Shape | Files | Served as |
|---|---|---|
| Frontend + server | `app/` (→ `app/dist/`) + `server/server.js` | static frontend + `/api/*` → server |
| Server-only | standalone `server.js` | `/api/*` → server (no static) |
| Frontend-only | standalone `package.json` (no server) | static frontend only |
| Docker (any runtime) | `Dockerfile` | whole subdomain → container on `TOOLSTEAD_PORT` |

The runner auto-detects node shapes. For Docker, set `runtime.type: "docker"` and (optionally)
`runtime.dockerfile`.

---

## `app.json` field reference

| Field | Req | Notes |
|---|---|---|
| `schemaVersion` | yes | `"1"` |
| `slug` | yes | `^[a-z0-9-]+$`, immutable identity (process/container/DB name) |
| `name` | yes | display name |
| `description` | no | shown in the admin UI |
| `subdomain` | yes | `^[a-z0-9-]+$`; app served at `https://<subdomain>.<base-domain>` (mutable) |
| `source.branch` | no | default `main` |
| `source.repoPath` | no | subdir to deploy from (monorepos) |
| `source.githubRepo` | no | `owner/repo`; can also be set via CLI/admin |
| `runtime.type` | yes | `node` or `docker` |
| `runtime.buildCommand` | no | node only; default `npm run build` |
| `runtime.dockerfile` | no | docker only; default `Dockerfile` |
| `auth.mode` | yes | `platform` or `public` |
| `database.mode` | yes | `internal`, `external`, or `none` |
| `storage.mode` | yes | `internal`, `external`, or `none` |
| `env[]` | no | declared variable *names* + metadata (see below) |

`env[]` entries: `key` (UPPER_SNAKE_CASE, not `TOOLSTEAD_*`), `secret` (bool), `required` (bool),
`default` (string, non-secret only), `description`.

## Reserved `TOOLSTEAD_*` environment catalog

The app **reads** these; it never sets or declares them. "auto" = generated by the platform;
"user-required" = an operator must set it before deploy (external modes).

| Variable | Present when | Source | Meaning |
|---|---|---|---|
| `TOOLSTEAD_APP_SLUG` | always | auto | app slug / identity |
| `TOOLSTEAD_APP_NAME` | always | auto | display name |
| `TOOLSTEAD_APP_URL` | always | auto | public URL |
| `TOOLSTEAD_BASE_DOMAIN` | always | auto | platform base domain |
| `TOOLSTEAD_PORT` | always | auto | **the port the server MUST bind** |
| `TOOLSTEAD_ENV` | always | auto | deploy environment (e.g. `production`) |
| `TOOLSTEAD_DATABASE_URL` | database≠none | auto (internal) / user-required (external) | connection string (same name both modes) |
| `TOOLSTEAD_DATABASE_ENGINE` | database≠none | auto | `postgres` |
| `TOOLSTEAD_STORAGE_ENDPOINT` | storage≠none | auto / user-required | S3 endpoint |
| `TOOLSTEAD_STORAGE_REGION` | storage≠none | auto / user-required | S3 region |
| `TOOLSTEAD_STORAGE_BUCKET` | storage≠none | auto / user-required | bucket |
| `TOOLSTEAD_STORAGE_PREFIX` | storage=internal | auto | per-app key prefix |
| `TOOLSTEAD_STORAGE_ACCESS_KEY` | storage≠none | auto / user-required | S3 access key |
| `TOOLSTEAD_STORAGE_SECRET_KEY` | storage≠none | auto / user-required | S3 secret key |
| `TOOLSTEAD_AUTH_URL` | auth=platform | auto | control-plane `/verify` base |
| `TOOLSTEAD_APP_ID` | auth=platform | auto | = slug |
| `TOOLSTEAD_APP_SECRET` | auth=platform | auto | app secret for `/verify` |
| `TOOLSTEAD_APP_JWT_SECRET` | auth=platform | auto | sign your own sessions with this |

Plus the one documented unprefixed alias: `PORT = TOOLSTEAD_PORT`.

**Why one name for internal & external:** `TOOLSTEAD_DATABASE_URL` and the `TOOLSTEAD_STORAGE_*`
set have identical names whether the resource is internal or external. The app reads one variable
and never knows the difference; graduating internal→external is a value change, not a code change.

## Worked examples

### A. Internal everything (the easy path)
```json
{ "schemaVersion":"1","slug":"notes","name":"Notes","subdomain":"notes",
  "source":{"branch":"main"},"runtime":{"type":"node"},
  "auth":{"mode":"platform"},"database":{"mode":"internal"},"storage":{"mode":"internal"} }
```
Postgres DB + storage prefix auto-provisioned and injected. Connect a repo, `toolstead deploy:watch`.

### B. External DB + external storage (heavier path)
```json
{ "schemaVersion":"1","slug":"crm","name":"CRM","subdomain":"crm",
  "source":{"branch":"main"},"runtime":{"type":"node","buildCommand":"npm run build"},
  "auth":{"mode":"platform"},"database":{"mode":"external"},"storage":{"mode":"external"} }
```
Deploy is blocked until you set the creds:
```bash
toolstead set-secret TOOLSTEAD_DATABASE_URL 'postgresql://…@neon…'
toolstead set-secret TOOLSTEAD_STORAGE_ENDPOINT 'https://…r2.cloudflarestorage.com'
toolstead set-secret TOOLSTEAD_STORAGE_ACCESS_KEY '…'   # + REGION / BUCKET / SECRET_KEY
```

### C. Static-only, public (no server, no auth)
```json
{ "schemaVersion":"1","slug":"landing","name":"Landing","subdomain":"hello",
  "source":{"branch":"main"},"runtime":{"type":"node","buildCommand":"npm run build"},
  "auth":{"mode":"public"},"database":{"mode":"none"},"storage":{"mode":"none"} }
```

### D. Dockerfile app (any runtime)
```json
{ "schemaVersion":"1","slug":"py-tool","name":"Python Tool","subdomain":"pytool",
  "source":{"branch":"main","repoPath":"service"},
  "runtime":{"type":"docker","dockerfile":"Dockerfile"},
  "auth":{"mode":"platform"},"database":{"mode":"internal"},"storage":{"mode":"none"},
  "env":[{"key":"WORKERS","required":false,"default":"2"}] }
```
The container must listen on `TOOLSTEAD_PORT` and answer `GET /health`.

## Using the injected resources

**Database** (Postgres, internal or external — same code):
```js
import postgres from 'postgres';
const sql = postgres(process.env.TOOLSTEAD_DATABASE_URL);
```

**Object storage** (S3 SDK, internal or external — same code):
```js
import { S3Client } from '@aws-sdk/client-s3';
const s3 = new S3Client({
  endpoint: process.env.TOOLSTEAD_STORAGE_ENDPOINT,
  region: process.env.TOOLSTEAD_STORAGE_REGION,
  credentials: { accessKeyId: process.env.TOOLSTEAD_STORAGE_ACCESS_KEY, secretAccessKey: process.env.TOOLSTEAD_STORAGE_SECRET_KEY },
  forcePathStyle: true
});
// scope your keys under process.env.TOOLSTEAD_STORAGE_PREFIX when storage is internal
```

**Auth** — see the root `AGENTS.md` §5 and `examples/starter-app/server/server.js`.

## Deploy & observe

```bash
export TOOLSTEAD_URL=https://admin.example.com
export TOOLSTEAD_TOKEN=tk_...          # scoped token (admin UI → Tokens)

toolstead apply                         # create/connect/provision from app.json
toolstead set-secret OPENAI_API_KEY     # (reads value from stdin)
toolstead deploy:watch                  # deploy + stream log to terminal status
toolstead logs --lines 200
toolstead status
```

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `deploy` returns "Missing required variables" | Set them: `toolstead set-secret KEY`. External DB/storage creds + `required` declared vars all gate the deploy. |
| App 502s after deploy | Server isn't binding `TOOLSTEAD_PORT`, or crashed — check `toolstead logs`. |
| `/api/...` 404s | Server routes must be under `/api`; Caddy only proxies `/api/*` to the server. |
| Login returns 403 | The user hasn't been granted access to this app's slug (admin UI → Users). |
| Frontend loads but blank | `buildCommand` didn't produce `app/dist/` — check the deploy log. |
| Health probe never healthy | Add `GET /health` → 200. |
| Docker app unreachable | Container must listen on `TOOLSTEAD_PORT` and be the foreground process. |
